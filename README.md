# Promotion Dizad — منصة التجارة الإلكترونية والتسويق بالعمولة

منصة عربية (RTL كاملة) للسوق الجزائري تربط **الموردين** بـ**المسوقين** و**المشترين**،
بالاسم والشعار الحاليين للمشروع دون تغيير.

## نموذج العمل (ملزم وموثق)

- المورد يوفّر المنتجات والمخزون ويجهّز الطلبيات ويتعامل مع شركة التوصيل التي يتعاقد معها.
- المسوق يجلب الطلبات عبر روابط إحالة فريدة مقابل عمولة من هامش المنصة.
- المشتري يطلب ويدفع **عند الاستلام** لشركة توصيل المورد.
- المنصة تدير المنتجات والطلبات والإحالات والعمولات آلياً — **لا تشتري مخزوناً، لا تستلم أموال الزبائن، ولا تدير التوصيل بنفسها**.
- العمولة «متوقعة» عند إنشاء الطلب ولا تصبح «مستحقة» إلا بعد حالة **تم التسليم والتحصيل**.
  الطلبات الملغاة/المرفوضة/المرتجعة تُلغى عمولاتها آلياً ويُعاد مخزونها.
- الأسعار والعمولات تُحفظ **Snapshot** داخل كل طلب — تغيير الأسعار لاحقاً لا يغيّر الطلبات القديمة.
- قاعدة الإحالة: **آخر رابط صالح نقره المشتري خلال 30 يوماً** يُنسب إليه الطلب. لا عمولة لمسوق اشترى عبر رابطه.

## التشغيل المحلي (مجاني 100%)

```bash
cd ~/workspace/promotion-dizad-platform
npm start
```

ثم افتح http://localhost:4173 — عند أول تشغيل تظهر شاشة **إعداد المدير الأول**
(الاسم، الهاتف، كلمة مرور تختارها أنت — لا توجد كلمة مرور افتراضية في الكود).

## تتبع الطلبات

- صفحة «تتبّع طلبك» مخصصة في التطبيق: بالرقم المرجعي + الهاتف تظهر المرحلة الحالية على خط زمني بصري من 6 مراحل، السجل الزمني الكامل بتواريخه، منتجات الطلب، تفاصيل المبالغ، ورسائل واضحة عند الإلغاء/الرفض/الإرجاع/تعذر التسليم.
- بعد إتمام أي طلب يُنقل المشتري مباشرة إلى صفحة التتبع وطلبُه معروض.
- المستخدم المسجل يرى في نفس الصفحة كل طلباته المرتبطة بدوره (مشتري/مسوق/مورد/إدارة) مع زر «السجل الزمني» لكل طلب — ولا يرى إلا طلباته (يُخفي عن المسوق بيانات اتصال المشتري).

## التقنية

- Node.js فقط (وحدات مدمجة: http, crypto/scrypt, node:sqlite) — **صفر اعتماديات خارجية، صفر تكاليف تشغيل للكود نفسه**.
- قاعدة بيانات SQLite بملف واحد داخل `data/` (مجلد مهمل في Git)، مع نسخ احتياطي بزر من لوحة الإدارة (`VACUUM INTO`).
- جلسات بكوكيز HttpOnly + حماية CSRF + قفل الحساب بعد 5 محاولات فاشلة + حدّ معدّل للطلبات الحساسة.
- كل العمليات الحساسة (الأسعار، المخزون، العمولات) تُحسب وتُتحقق في الخادم داخل معاملات قاعدة بيانات.

## التكاملات — حالتها الصادقة

| التكامل | الحالة | ما ينقصه |
|---|---|---|
| مشاركة واتساب/تيليغرام/فيسبوك + مراسلة m.me | ✅ تعمل الآن (روابط رسمية) | لا شيء |
| إشعارات تيليغرام آلية للمورد/المسوق | ⚙️ الكود جاهز ومختبَر منطقياً | توكن بوت من BotFather في `TELEGRAM_BOT_TOKEN` + Chat ID في حساب كل مستخدم |
| إشعارات واتساب آلية | ⚙️ الكود جاهز عبر Meta Cloud API | تفعيل WhatsApp Business Platform — قد تنطبق رسوم رسائل من Meta، لا يُفعَّل دون موافقة صاحب المنصة |
| دمج رسائل صفحة فيسبوك في لوحة الدعم | ⚙️ endpoint جاهز للضبط | تطبيق Meta + توكن صفحة + مراجعة صلاحيات من Meta |

الإشعارات التي لا تجد تكاملاً مضبوطاً تبقى في الطابور بحالة `queued_not_configured`
وتظهر في لوحة الإدارة مع زر إعادة محاولة — لا تدّعي المنصة إرسال ما لم يُرسل.

## النشر المجاني — خيارات حقيقية بحدودها

الكود يعمل على أي استضافة Node مجانية، لكن لا توجد استضافة مجانية «دائمة التشغيل» مضمونة إلى الأبد:

1. **Render (Free Web Service)** — ينام بعد الخمول ويستيقظ ببطء؛ قاعدة SQLite تُمسح عند إعادة النشر ما لم تُستخدم خدمة قرص (قد تكون مدفوعة) — مناسب كتجربة محدودة (المرحلة 9).
2. **حاسوبك الخاص + Cloudflare Tunnel (مجاني)** — تحكّم كامل وقاعدة البيانات عندك، لكن يجب أن يبقى الحاسوب مشغّلاً.
3. **أي VPS لاحقاً** — خارج شرط «مجاني 100%» ويتطلب موافقة صريحة قبل أي تكلفة.

النشر الفعلي يحتاج قرار صاحب المنصة (اختيار المضيف) + إنشاء حساب المدير بنفسه.

## ملاحظات صدق تنفيذية

- كتالوج المنصة يبدأ **فارغاً عن قصد**: منتجات سوقلي الحالية في المتجر القديم بلا موردين متعاقدين ولا أسعار جملة موثقة، فلم تُستورد كمنتجات حقيقية. أول منتج يظهر هو أول منتج يعتمده مورد حقيقي عبر المنصة.
- البلديات: حقل إلزامي مُتحقق منه كنص ضمن الطلب. قاعدة البلديات الرسمية الكاملة (1541 بلدية) تُستورد كملف بيانات عند توفرها ولا تُختلق.
- استعادة كلمة المرور تُسلَّم عبر قنوات الإشعار المضبوطة (تيليغرام/سجل الإدارة محلياً) — لا توجد خدمة بريد/SMS مجانية مضبوطة بعد.
